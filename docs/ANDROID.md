# SeaYou for Android

SeaYou is distributed as an Android app through Google Play. The React interface in `apps/web`
is **bundled inside the app** with [Capacitor](https://capacitorjs.com) 8.5 and runs in the
Android WebView from `https://localhost`; nothing of the interface is loaded from a website, and
no web version of SeaYou is published (`docs/DEPLOYMENT.md`). The app calls the SeaYou API over
HTTPS; the API also serves the public pages the app links to (support, legal documents, account
deletion, password reset).

| | |
| --- | --- |
| Application ID | `io.github.liadlati.seayou` — permanent once published (`apps/web/capacitor.config.ts`, `android/app/build.gradle`) |
| Debug build | `io.github.liadlati.seayou.dev`, version `…-dev`: installs beside the Play version |
| Target / compile SDK | 36 (Android 16) — the Google Play requirement for new apps and updates since 31 August 2026 |
| Minimum SDK | 24 (Android 7.0) |
| Version | `apps/web/android/version.properties` (`versionCode`, `versionName`) |
| Permissions | `INTERNET` only |
| Project | `apps/web/android` (generated by Capacitor, then adjusted; committed) |

## How the app finds the server

`apps/web/src/lib/endpoints.ts` is the one place that knows where the server is.

- In the browser during development the API shares the page's origin through the Vite proxy, so
  every path stays relative (`/api/…`, `/support`).
- In the Android app the interface is served from `https://localhost`, where a relative `/api`
  would ask the phone itself. The app is therefore built with **`VITE_MIB_API_ORIGIN`**, the API's
  public origin, baked in at build time. An app built without it shows "SeaYou cannot start"
  instead of silently calling itself.
- The API accepts that origin through CORS: `MIB_CORS_ORIGIN` defaults to `https://localhost` in
  production (`apps/api/src/config.ts`).

Links to the support and legal pages are absolute URLs on the API origin; Android opens them in
the person's browser. `mailto:` links on the support page open their mail app.

## Two build modes

| | `android:dev` | `android:release` |
| --- | --- | --- |
| API origin | `VITE_MIB_API_ORIGIN`, default `http://10.0.2.2:3001` (the host computer, seen from the emulator) | `VITE_MIB_API_ORIGIN`, **required**, `https://`, not a local, private or placeholder host |
| Plain http | Allowed to `10.0.2.2` and `localhost` only, in the debug build only (`src/debug/…/network_security_config.xml`) | Refused (`usesCleartextTraffic="false"`, no mixed content) |
| Gradle task | `assembleDebug` | `bundleRelease` (refuses anything not built by `android:release`) |

`scripts/android-build.mjs` builds the production bundle (development controls exist only under
`vite dev`, never in either mode), refuses a release whose origin is unfit or whose bundle mentions
a development address, records the mode in `dist/seayou-build.json`, and runs `cap sync android`.
The release Gradle build checks that record, the Capacitor config (no mixed content, no remote
`server.url`) and the upload key before it packages anything. No secret is ever bundled: the
interface contains only the public API origin.

## Setting up Windows (once)

1. Install **Node.js 22** and enable pnpm: `corepack enable` (PowerShell as administrator).
2. Install **Android Studio** (current stable). In *More Actions → SDK Manager* install:
   *Android 16 (API 36) SDK Platform*, *Android SDK Build-Tools*, *Android SDK Platform-Tools*,
   *Android Emulator*. Android Studio's bundled JDK (JBR 21) is what Gradle uses.
3. In *Device Manager*, create a phone (for example Pixel 8) with a **Google Play** system image
   for API 36, x86_64.
4. Tell the tools where the SDK is (PowerShell, once per user):

   ```powershell
   [Environment]::SetEnvironmentVariable('ANDROID_HOME', "$env:LOCALAPPDATA\Android\Sdk", 'User')
   [Environment]::SetEnvironmentVariable('JAVA_HOME', 'C:\Program Files\Android\Android Studio\jbr', 'User')
   ```

   Open a new PowerShell window afterwards. `adb` is in `%ANDROID_HOME%\platform-tools`.
5. In the repository: `pnpm install`.

## Running the development app in the emulator

In one PowerShell window, the API in development mode, accepting the app's origin:

```powershell
cd apps\api
$env:MIB_DEV_MODE = 'true'
$env:MIB_CORS_ORIGIN = 'http://localhost:5173,https://localhost'
$env:MIB_APP_URL = 'http://localhost:3001'
pnpm db:seed          # only for a fresh development database
pnpm dev
```

In a second window, build the interface for the emulator and install the app:

```powershell
pnpm --filter @mib/web android:dev
cd apps\web\android
.\gradlew.bat assembleDebug
& "$env:ANDROID_HOME\emulator\emulator.exe" -list-avds            # start one from Device Manager
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
```

Then open **SeaYou** on the emulator. What to check, in order:

1. **Sign in** with a development account (or register), choose a harbour.
2. **Send a letter** to a friend.
3. **Receive a letter**: sign out, sign in as the friend (or use a second emulator). In a desktop
   browser at `http://localhost:5173`, sign in as a developer and use the DEV panel to move the
   clock past the arrival. Pick the bottle up on My Shore.
4. **Support**: Profile → Help & Support opens `/support` in the browser; its buttons open the mail
   app.
5. **Password reset**: Forgot password? on the sign-in screen. In development the message is in
   the DEV panel's outbox; its link opens the server's reset page (`/reset-password`) on the PC.
6. **Account deletion**: Profile → Delete account.
7. **Android behaviour**: Back closes an open dialog, then steps back through screens, then sends
   SeaYou to the background from the first screen. Rotate the phone while writing a letter (the
   letter stays). Type a letter and check the field stays above the keyboard. Check nothing hides
   under the status bar, the camera cut-out or the gesture bar, in both orientations.
8. **Lifecycle**: switch to another app and back (the letter is still there); swipe SeaYou away
   and reopen it (you are asked to sign in again — see "Sessions on Android" below).

`adb logcat -s Capacitor chromium` shows the WebView console. `chrome://inspect` on the PC
attaches Chrome DevTools to the debug app (debug builds only).

## Building the release for Google Play

### The upload key (once)

Google Play signs what users download with the **app signing key**, which Google keeps (Play App
Signing, mandatory for new apps). You sign uploads with your own **upload key**. Create it once and
keep it, and its passwords, **outside the repository**, backed up somewhere safe:

```powershell
& "$env:JAVA_HOME\bin\keytool.exe" -genkeypair -v -keystore "$HOME\seayou-keys\seayou-upload.jks" `
  -alias seayou-upload -keyalg RSA -keysize 4096 -validity 10000
```

Then either create `apps\web\android\keystore.properties` (ignored by Git):

```properties
storeFile=C:\\Users\\<you>\\seayou-keys\\seayou-upload.jks
storePassword=<store password>
keyAlias=seayou-upload
keyPassword=<key password>
```

or set `SEAYOU_UPLOAD_STORE_FILE`, `SEAYOU_UPLOAD_STORE_PASSWORD`, `SEAYOU_UPLOAD_KEY_ALIAS` and
`SEAYOU_UPLOAD_KEY_PASSWORD` in the environment of the build. `.gitignore` excludes
`keystore.properties`, `*.jks`, `*.keystore`, `*.p12` and `*.pem`; never commit any of them. A lost
upload key can be reset through Play Console support; a leaked one must be.

### Each release

1. Raise `versionCode` by one (and `versionName` as you like) in
   `apps/web/android/version.properties`, and commit that.
2. Build:

   ```powershell
   $env:VITE_MIB_API_ORIGIN = 'https://<the API domain>'
   pnpm --filter @mib/web android:release
   cd apps\web\android
   .\gradlew.bat clean bundleRelease
   ```

3. The upload is `apps\web\android\app\build\outputs\bundle\release\app-release.aab`.
   To try the exact release on a device first, `.\gradlew.bat assembleRelease` produces
   `app\build\outputs\apk\release\app-release.apk` (signed with the upload key; install it with
   `adb install -r`).

## Sessions and storage on Android

The app keeps exactly what the Privacy Policy lists (section 5), in the WebView's private storage:
the session token and the unsent letter in `sessionStorage`, the account's time zone in
`localStorage`. On Android `sessionStorage` lives as long as the app's process: switching apps,
rotating and locking the phone keep it; swiping SeaYou away, or Android ending it in the
background after a while, clears it, and the person signs in again. This is deliberate and
matches the published policy. Keeping people signed in across restarts would mean storing the
token persistently, which requires a Privacy Policy change first.

Backups: the app opts out of Android Auto Backup and device-to-device transfer
(`res/xml/data_extraction_rules.xml`), so no token or time zone is copied to Google Drive or a new
phone.

## Before the first Play Console upload

- **Decisions only you can make**: the application ID above (permanent once published); the price
  and the countries; the API's production domain (used for `VITE_MIB_API_ORIGIN` and
  `MIB_APP_URL`).
- **Store listing**: title, short and full description, **phone screenshots** (at least two), a
  **feature graphic** (1024 × 500), and the icon `apps/web/android/store/play-icon-512.png`
  (generated from the brand symbol by `apps/web/scripts/android-assets.mjs`).
- **Policy links**: Privacy Policy `https://<API domain>/legal/privacy`; account deletion
  `https://<API domain>/legal/delete-account`.
- **Data safety form** (`docs/LEGAL_DOCUMENTS.md`): collected — email address, username, user
  content (letters, reports and appeals), time zone; encrypted in transit; deletion available in
  the app and on the web; no data shared with third parties for advertising; no analytics.
- **Content rating** questionnaire, **target audience** (not directed at children; the Terms set
  a minimum age), and whether the app contains user-generated content (it does: reporting and
  blocking are in place).
- **Merchant account** for a paid app, and a **closed test** track if Play requires testing
  before production for a new personal developer account.

## Paid download and unofficial copies

SeaYou is a paid download with no in-app purchases, and the app contains no payment flow.
**Paying on Google Play does not currently protect the service.** Anyone holding a copy of the
APK — extracted from a phone, shared by a buyer, or rebuilt from this source — can install it,
register an account and use the API exactly like a buyer, because the API never asks for proof of
purchase. The API is also reachable with any HTTP client, so no client change alone (including not
publishing the web interface) proves a purchase; it only removes the most convenient way in.

The smallest sound remedy is to **gate account creation on a Google Play Integrity verdict**:

1. At registration the app asks the server for a one-time nonce, then requests a Play Integrity
   token for it (a small Capacitor plugin around `IntegrityManager`).
2. The API decodes the token with Google (a service account with the Play Integrity API enabled,
   linked to the Play Console app) and accepts the registration only if the verdict says the app
   is `PLAY_RECOGNIZED` with the expected package name and signing certificate, and the licensing
   verdict is `LICENSED` (the Google account installed it from Play, that is, bought it).
3. Existing accounts and sign-in are unaffected, so a buyer who changes phone keeps their account.

This needs a Google Cloud project and a service-account secret on the server, a Privacy Policy
addition (Play Integrity sends app and device signals to Google), a Data safety update, and a
fallback for devices without Google Play services. It limits new accounts to people who obtained
SeaYou from Play; it does not stop someone who registered legitimately from using a modified
client afterwards. It is not implemented: it is a product and cost decision (Integrity quotas,
Google Cloud setup) for you to make.

## Regenerating the Android project

The project was created with `pnpm exec cap add android` and then adjusted: manifest,
resources, `app/build.gradle`, `build.gradle`, `version.properties`, icons and splash. If it ever
has to be recreated, redo those adjustments; `pnpm exec cap sync android` (run by the build
scripts) is always safe and never touches them.
